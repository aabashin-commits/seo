# seo-crawl — обход сайта для аудита

Заменяет Screaming Frog и Netpeak Spider на малых и средних проектах. Без внешних
зависимостей, работает на Node 18+.

## Запуск

```bash
node .claude/skills/seo-crawl/scripts/crawl.mjs <домен> [опции]
```

| Опция | По умолчанию | Назначение |
|---|---|---|
| `--limit N` | 500 | Максимум страниц |
| `--delay MS` | 300 | Пауза между запросами, мс |
| `--out FILE` | `crawl.csv` | Путь основного отчёта |
| `--ignore-robots` | выкл | Игнорировать Disallow — **см. ограничения** |

Протокол можно не указывать: `searchfit.ai` превратится в `https://searchfit.ai/`.

### Типовой вызов

```bash
node .claude/skills/seo-crawl/scripts/crawl.mjs example.ru \
  --limit 500 --delay 300 \
  --out projects/example/data/crawl-2026-08-25.csv
```

## Что делает

1. Читает `robots.txt`, разбирает `Disallow`, `Allow` и `Sitemap` для `User-agent: *`.
2. Загружает sitemap (включая sitemap-индексы, до 3 уровней вложенности).
3. Обходит сайт в ширину от главной, считая глубину в кликах.
4. Не выходит за пределы хоста; внешние ссылки только считает.
5. Редиректы не следует автоматически — фиксирует цель и ставит её в очередь,
   поэтому цепочки видны в отчёте.
6. Пишет два CSV в UTF-8 с BOM и печатает сводку в консоль.

## Выход

**Основной отчёт** — строка на URL, 26 колонок:

```
url, status, redirect_to, depth, found_on, in_sitemap, content_type,
title, title_len, description, description_len, h1, h1_count, h2_count,
canonical, canonical_self, meta_robots, noindex, words, images, images_no_alt,
hreflang, jsonld, links_total, links_internal, error
```

**Отчёт по битым ссылкам** — файл `<имя>-broken.csv`:
`broken_url, status, found_on`. Колонка `found_on` показывает, с какой страницы
стоит битая ссылка — по ней и правят.

**Сводка в консоли** — готовые цифры для раздела аудита: коды ответа, дубли title
и description, страницы без h1, noindex, canonical не на себя, тонкий контент,
глубина больше 3 кликов, изображения без alt.

## Как читать результат

| Находка в сводке | Что это значит | Куда дальше |
|---|---|---|
| Ошибки 4xx, битые ссылки | Мёртвые ссылки внутри сайта | `docs/02-tech-audit.md`, раздел «Доступность» |
| Редиректы 3xx в большом числе | Возможны цепочки, теряется вес | Проверь `redirect_to` на цепочки |
| Дубли title / description | Шаблон мета не настроен | `docs/05-content-onpage.md` |
| h1 отсутствует или больше одного | Ошибка вёрстки шаблона | `docs/02-tech-audit.md` |
| canonical не на себя | Страница отдаёт вес другой | Проверь намеренность |
| noindex на нужных страницах | Страницы исключены из поиска | Критично, уровень P0 |
| Тонкий контент | Кандидаты на доработку или склейку | `docs/05-content-onpage.md` |
| Глубина больше 3 кликов | Проблема перелинковки | `docs/05-content-onpage.md` |
| `in_sitemap = 0` при коде 200 | Страница не в sitemap | Проверь полноту sitemap |
| `noindex = 1` при `in_sitemap = 1` | Прямое противоречие сигналов | Критично |

## Ограничения — знай до запуска

- **Только серверный HTML.** JavaScript не выполняется. Если контент появляется
  после рендера, краулер увидит пустую страницу. **Это сама по себе находка** —
  сравни результат с рендером через Playwright MCP и вынеси в аудит.
- **Скорость и Core Web Vitals не измеряются.** Для CWV используй PageSpeed Insights
  или скилл плагина `technical-seo`.
- **Внешние ссылки не проверяются** на доступность — только считаются. Проверку
  внешних ссылок делает скилл плагина `broken-links`.
- **Потолок примерно 500 страниц.** Для больших сайтов нужен Screaming Frog.
  Можно обойти частями через `--limit` и старт с разных разделов.
- **Одиночные запросы, без параллельности.** 500 страниц при задержке 300 мс —
  около 3 минут. Не уменьшай задержку ниже 200 мс на боевом сайте клиента.

## Правила использования

1. **Только по домену, доступ к которому подтверждён** карточкой проекта или прямым
   указанием человека. Краул чужого сайта без основания не запускается.
2. **`robots.txt` уважается по умолчанию.** Флаг `--ignore-robots` применяется только
   на сайте клиента, только когда нужно увидеть закрытые от индексации разделы,
   и только с явного согласия. На чужом сайте — никогда.
3. **Задержка не ниже 200 мс.** Краулер не должен создавать нагрузку.
4. **Результат кладётся в `projects/<клиент>/data/`**, а не в `deliverables/`.
   Это сырьё, клиенту оно не отдаётся.
5. **Сводка из консоли — не отчёт.** Это входные данные для аудита, которые ты
   интерпретируешь по `docs/02-tech-audit.md` и приоритизируешь по `docs/07-reporting.md`.
