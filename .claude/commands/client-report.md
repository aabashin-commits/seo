Собери отчёт клиенту для: **$ARGUMENTS**

## Порядок

1. **Прочитай карточку проекта** — тон коммуникации, стоп-темы, кто вносит правки,
   цель на период.

2. **Собери всё из `work/`** по этому проекту. Разбери противоречия между источниками
   (вывод плагина против ручной проверки — верна ручная проверка).

3. **Приоритизируй** по `docs/07-reporting.md`, модель «эффект × трудозатраты»:
   - Эффект: высокий / средний / низкий + обоснование в одну строку, за счёт чего
   - Трудозатраты: в часах, с указанием исполнителя
   - Отдельным блоком сверху — **быстрые победы** (высокий эффект, до 2 часов)

4. **Переформулируй каждую задачу** под CMS клиента (`docs/09-cms-playbooks.md`).
   Клиент на Tilda получает пошаговую инструкцию с путём в интерфейсе.
   Самописный сайт — тикет разработчику с «было → стало» и критерием проверки.
   Формулировки вида «оптимизировать мета-теги» недопустимы.

5. **Оформи** по `templates/audit-report.md` (или сокращённо для месячного отчёта:
   что сделано → динамика → что изменилось не по нашей вине → что дальше →
   **что блокирует работу на стороне клиента**).

6. **Подготовь файлы под Google Drive:**
   - Markdown: заголовки через `#`, таблицы обычным синтаксисом, без HTML внутри
   - CSV: UTF-8 **с BOM**, разделитель `,`, значения с запятыми в кавычках,
     числа без пробелов и валюты, даты `ГГГГ-ММ-ДД`
   - Имена файлов: `<тип>-<домен>-<ГГГГ-ММ-ДД>.<ext>`
   - Сложи в `deliverables/`

7. **Проверь CSV перед сдачей** — открой и убедись, что колонки не разъехались
   на строках с запятыми внутри значений.

## Обязательно

- Резюме написано последним и стоит первым.
- Каждое число с источником и датой.
- Пометки `[факт]` / `[оценка]` / `[плагин]` расставлены.
- Позиции и сроки выхода в топ **не обещаны** — обещаны выполненные работы
  и описан ожидаемый эффект.
- Раздел «Нужны данные» заполнен.
- Ничего из `work/` не перенесено копированием — всё переписано.

**Файлы не отправляй.** Сообщи, что готово и где лежит — заливает человек.
