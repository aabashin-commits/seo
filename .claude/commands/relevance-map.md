Построй карту релевантности для: **$ARGUMENTS**

## Порядок

1. **Прочитай карточку проекта** и `data/semantic-core.csv`.
   Ядра нет — сначала `/semcore`.

2. **Выбери ветку кластеризации** по `docs/04-clustering.md`:
   - Есть выгрузка SERP (Топвизор, KeyAssort, Serpstat) → **ветка A**: hard-кластеризация
     по пересечению топ-10, порог **4 общих URL** по умолчанию
   - Данных нет → **ветка B**: группировка по интенту, затем ручная проверка
     выдачи для 20 % кластеров (обязательно самых крупных и спорных)

   Выбранную ветку и порог зафиксируй в отчёте явно.

3. **Учти обе ПС.** Проект продвигается в Яндексе и Google — кластеризуй отдельно
   по каждой. Расхождения фиксируй, приоритет отдавай ПС с большим трафиком
   по данным Метрики/GA4; нет данных — коммерция в приоритет Яндексу.

4. **Черновая группировка плагином.** Скилл `keyword-clustering` или
   `/keyword-cluster <keywords> [intent]`. Вывод → `work/`, затем пересобери
   под регион и Яндекс. Прямо в карту его переносить нельзя.

5. **Назначь страницы.** Для каждого кластера:
   - тип страницы (услуга / категория / статья / карточка / гео-посадочная)
   - `target_url` и статус: `есть` / `создать` / `объединить` / `удалить`
   - черновые title и description по формулам из `docs/05-content-onpage.md`

   Правила: один кластер — одна страница; один запрос — один кластер;
   нет подходящей страницы — ставь `создать`, а не назначай ближайшую по смыслу.

6. **Проверь каннибализацию:**
   - Есть GSC/Вебмастер — более одного URL с показами по одному запросу
   - Нет доступов — `site:домен запрос` в обеих ПС
   - Всегда — повторы `target_url` и `main_query` в самой карте
   Найденное вынеси в задачи с решением (301 / canonical / развести интенты).

7. **Выгрузи** `deliverables/relevance-map-<домен>-<дата>.csv`, UTF-8 с BOM, колонки:
   `cluster,main_query,freq_exact_sum,intent,page_type,target_url,url_status,title,description,priority,note`

## Проверка перед сдачей

- Каждый запрос ядра в ровно одном кластере либо помечен отброшенным.
- У каждого кластера есть тип страницы и `target_url`.
- Кластеров `создать` не больше, чем клиент реально осилит.
- Порог указан явно (ветка A) или проверено 20 % кластеров (ветка B).
- Каннибализация проверена, конфликты вынесены в задачи.
- Гео-кластеры получили отдельные страницы под города, а не один список городов.
