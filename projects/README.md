# Проекты

Одна папка на клиента. Структура одинаковая у всех.

```
projects/<клиент>/
├── project-profile.md      карточка проекта — читается первой в любой сессии
├── data/                   сырые данные
│   ├── crawl-<дата>.csv
│   ├── crawl-<дата>-broken.csv
│   ├── semantic-core.csv
│   ├── gsc-<дата>.csv
│   └── ai-visibility-<дата>.csv
├── work/                   черновики и непроверенное
│   ├── plugin-audit-<дата>.md      вывод SearchFit как есть
│   ├── yandex-check-<дата>.md
│   └── commercial-<дата>.md
└── deliverables/           только то, что уходит клиенту
    ├── audit-<домен>-<дата>.md
    ├── task-list-<домен>-<дата>.csv
    ├── relevance-map-<домен>-<дата>.csv
    └── brief-<slug>-<дата>.md
```

## Правила

**`data/`** — сырьё как есть. Выгрузки, краулы, экспорт из сервисов. Не редактируется.

**`work/`** — всё промежуточное и всё, что ещё не проверено. Сюда же попадает вывод
плагина SearchFit в исходном виде.

**`deliverables/`** — только проверенное, оформленное и приоритизированное.
Файл не переезжает сюда копированием из `work/` — он переписывается.

**Доступы и пароли не хранятся нигде в этих папках.** В карточке проекта только
пометка, что доступ есть и где он лежит.

## Имена папок

Латиница, нижний регистр, дефис: `stroydom-kazan`, `klinika-zdorovie`.

## Завести новый проект

```bash
mkdir -p projects/<клиент>/{data,work,deliverables}
cp templates/project-profile.md projects/<клиент>/project-profile.md
```

Дальше — по `docs/01-project-onboarding.md`.
