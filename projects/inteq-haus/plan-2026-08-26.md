# Техаудит, семантика и 3-месячный план для inteq.haus (Tilda)

## Контекст

`inteq.haus` — сайт компании Inteq Haus, строительство фахверковых домов под ключ,
Москва и МО. Сайт на Tilda за DDoS-Guard, 115 URL в sitemap. Проект в Топвизоре уже
настроен и содержит 488 запросов с реальными позициями и частотностями.

Разведка 26.08.2026 показала, что сайт **уже неплохо ранжируется в Яндексе** (44,1%
запросов в топ-10), но упирается в две технические стены: каталог проектов не отдаёт
ссылок в HTML, и две проработанные коммерческие посадочные закрыты в `robots.txt`.
Задача не «вывести с нуля», а снять тормоза и дожать топ-30 → топ-10.

Работа ведётся по правилам `CLAUDE.md`: русский язык, Яндекс и Google равнозначны,
каждое число с источником и датой, факт и оценка разделены.

### Критические находки

**1. Каталог не отдаёт ссылок в HTML `[факт]`**
На `/projects` — **0 ссылок** на карточки `/projects/*` в исходном HTML. Карточки
рендерятся JS (`t-store__card`, блоки t951/t1002). На фильтровых лендингах
(`/odnoehtazhnye`, `/s-3-spalnyami`, `/shale`) — тоже **0 ссылок** на проекты.
Максимум ссылок на карточки — 5 штук с главной. То есть **19 из 24 карточек каталога
не получают внутреннего веса ниоткуда**, кроме sitemap. Яндекс исполняет JS хуже
Google — это прямой тормоз индексации и ранжирования карточек.

**2. Две коммерческие посадочные закрыты в robots.txt `[факт]`**
`/doma-karkasnye` и `/doma-iz-kleenogo-brusa` отдают 200, имеют проработанные title
(63 симв.), description, H1 и текст с H2 — но обе в `Disallow`. Клиент не знает,
почему. Запросные кластеры «каркасные дома» и «дома из клееного бруса» — крупные и
коммерческие.

**3. Тонкий контент на фильтровых лендингах `[факт]`**
Уникального текста 50–200 слов (общий объём страницы 682–871 слово, из них ~600 —
сквозные меню и футер). H2 — **ноль** на всех фильтровых лендингах, на `/projects`,
`/vypolnennye-proekty`, `/articles` и на карточках проектов. Размер HTML у лендингов
почти одинаковый (431–435 КБ) — страницы шаблонные, различаются только мета и фильтром.

**4. Изображения вне индекса `[факт]`**
На главной 104 уникальных картинки, но только 15 в теге `<img>`. Остальное — 98
`data-original` (JS-lazy) и 33 `background-image`, 188 атрибутов `t-bgimg`.
`loading="lazy"` — 0, WebP — 0. Для тематики «дома» поиск по картинкам — потерянный канал.

**5. Микроразметка почти пустая `[факт]`**
Везде только `BreadcrumbList` + `ListItem` (автоматика Tilda). `Organization` +
`PostalAddress` — только на `/contacts`. **На главной микроразметки нет вообще.**
Отсутствуют: `Product`/`Offer` на карточках, `Review`/`AggregateRating` на `/reviews`,
`FAQPage`, `Article` на статьях.

**6. Вес страниц `[факт]`**
HTML главной — 1,09 МБ, карточки `/projects/monterej` — 1,17 МБ. 43 файла JS/CSS на
главной. На Tilda глубоко не лечится.

**7. Возможная каннибализация `[оценка]`**
Две параллельные ветки с одинаковыми именами: `/projects/leon` ↔ `/dom-leon`,
`/projects/dajmond-bej` ↔ `/dom-dajmond-bej`, `/projects/flat-n-wood-330` ↔
`/dom-flat-n-wood-330`. Плюс 7 «Монтереев» в каталоге. Плюс пары коммерция↔инфо:
`/shale` ↔ `/articles/doma-shale`, `/haj-tek` ↔ `/articles/doma-haj-tek`,
`/odnoehtazhnye` ↔ `/articles/odnoehtazhnye-doma`. Клиент логику не знает — разбираем сами.

**8. Мелкое:** `<p>` внутри `<h1>` на статьях (невалидно, не критично); canonical
404-страницы указывает на `/oshibka`, который закрыт в robots.

### Топвизор — что реально есть `[факт]`

Проект `id=31725893`, сайт `inteq.haus`. Автосъём выключен (`on: 0`).

- **Яндекс Москва** (region_index 1, `region_key` 213, desktop) — съём 18.08.2026

- Конкуренты заведены: `fahverkdom.ru`, `domart.pro`, `velesadom.ru`

**Стартовая база позиций** (488 запросов):

| | топ-3 | топ-10 | топ-30 | топ-50 | топ-100 | вне |
|---|---|---|---|---|---|---|
| **Яндекс Москва**, 18.08.2026 | 84 (17,2%) | 131 (26,8%) | 196 (40,2%) | 37 (7,6%) | 22 (4,5%) | 18 (3,7%) |
| **Google Москва**, 25.08.2026 | 171 (35,0%) | 63 (12,9%) | — | — | — | 254 (52,0%) |

## Решения, зафиксированные на допросе

| Вопрос | Ответ |
|---|---|
| «Базовая автоматизация» | Опечатка. Нужен обычный 3-месячный план SEO-работ |
| Гео | Только Москва и МО. Регион в Вебмастере — Москва |
| KPI на 3 месяца | **Индексация и база**: вычистить техничку, завести ядро, переписать мета, загнать всё в индекс. Рост позиций — горизонт 4–6 мес. |
| Доступы | **Нет никаких.** Нужно прописать полный список |
| Правки на сайте | **Доступа в Tilda мне не дадут.** Все улучшения — письменные инструкции, которые ревьюит и применяет человек |
| Тексты | Пишу я, человек проверяет фактуру и вставляет |
| robots-блокировка | Разбираемся сами, приносим вердикт |
| Ветки `/projects/*` ↔ `/dom-*` | Разбираемся сами, вердикт по каждой паре в карте релевантности |
| Конкуренты | Определяем по выдаче (Топвизор уже знает троих — сверим) |

**Про API-ключ Топвизора.** Ключ и `User-Id` присланы в чат. По правилу 6 `CLAUDE.md`
**в файлы они не записываются** — ни в карточку проекта, ни в скрипты. В карточке будет
только пометка «доступ к Topvisor API есть, хранится в менеджере паролей». Ключ,
засвеченный в переписке, стоит перевыпустить в ЛК Топвизора.

## Этапы работ

### Этап 0. Каркас проекта

Создать структуру папок. Заполнить `project-profile.md` из
`templates/project-profile.md` — почти всё уже установлено разведкой. В блоке
«Доступы» — везде «нет», в «Пробелах в данных» — список из этапа 1.

### Этап 1. Деливерабл «Доступы и инструменты» — делается первым

Отдельный документ `deliverables/00-dostupy-i-instrumenty.md`, потому что без доступов
половина работ невыполнима, а запрашивать их надо одним письмом, а не по одному.

**Критично (без этого работа слепая):**

| Доступ | Зачем именно | Что без него нельзя |
|---|---|---|
| **Яндекс.Вебмастер** | Регион, индексация, фильтры, переобход, товарный фид | Проверить, назначен ли регион Москва; увидеть ЧС-фильтры; ускорить переобход после правок; узнать реальное число страниц в индексе |
| **Админка Tilda** | Применение всех правок | Ничего не применить; правки уходят человеку инструкциями |
| **Google Search Console** | Индексация, Core Web Vitals, запросы | Замерить базу по Google; `google-site-verification` уже на сайте — доступ у кого-то есть |
| **Яндекс.Метрика 80620486** | Поведенческие, конверсии, вебвизор | Отделить трафик от лидов; понять, какие страницы вообще посещают |

**Желательно:**

| Доступ | Зачем |
|---|---|
| Calltouch | Реальные звонки по страницам входа — иначе конверсия только `[оценка]` |
| Bitrix24 | Сквозная аналитика до сделки |
| Яндекс.Бизнес / Карты | Коммерческие факторы и локальная выдача Яндекса |
| Топвизор ЛК (не только API) | Кластеризатор и «Подбор слов» в интерфейсе |

**Инструменты, которые уже работают и доступов не требуют:**

- **Topvisor API** — позиции, 488 запросов, частотности Wordstat. Ключ есть.
- **Скилл `seo-crawl`** — обход 115 URL, заменяет Screaming Frog на этом объёме
- **Playwright MCP** — снятие топ-10 Яндекса для hard-кластеризации, проверка JS-рендера
- **Плагин SearchFit SEO** — `technical-seo`, `schema-markup`, `internal-linking`,
  `broken-links`. Вывод — черновик, идёт в `work/`, в `deliverables/` только после
  адаптации под Яндекс и Tilda (правило §6 `CLAUDE.md`)

**Чего нет и не будет:** Ahrefs/Semrush/Keys.so, Screaming Frog, Google Drive MCP.
Файлы готовим локально: `.md` под Google Docs, `.csv` UTF-8 с BOM под Sheets.

### Этап 2. Техаудит

Методика — `docs/02-tech-audit.md`, два чек-листа (общий + яндексовый).

1. **Полный обход** скиллом `seo-crawl` всех 115 URL → `data/crawl-2026-08-26.csv`:
   коды, редиректы, title/description/h1, canonical, noindex, объём текста, alt, глубина.
2. **Проверка JS-рендера**: Playwright против curl на `/projects` и фильтровых
   лендингах — зафиксировать, что именно появляется только после JS.
3. **Проверка каннибализации** по 3 парам `/projects/X` ↔ `/dom-X` и 3 парам
   коммерция↔инфо: сравнить title, H1, интент, позиции из Топвизора → вердикт по каждой.
4. **Судьба `/doma-karkasnye` и `/doma-iz-kleenogo-brusa`**: снять топ-10 Яндекса по
   «каркасные дома москва» и «дома из клееного бруса под ключ», оценить объём кластеров
   по Wordstat, сверить с позиционированием компании (фахверк) → аргументированный
   вердикт «открыть / переделать / удалить».
5. **Плагин** `technical-seo` и `broken-links` → `work/plugin-output/`, затем валидация
   по четырём осям (регион, коммерческие факторы, Wordstat вместо гугловых оценок,
   применимость к Tilda).

Выход: `deliverables/audit-2026-08-26.md` + `deliverables/task-list.csv`
(эффект × трудозатраты, блок «Быстрые победы» сверху).

### Этап 3. Семантика

Методика — `docs/03-semantics.md`. Стартовая база не пустая: 488 запросов из Топвизора.

1. Выгрузить 488 запросов + частотности (`volume:213:0:1/2/3`) → `data/topvisor-keywords-raw.csv`

## Что на Tilda сделать нельзя — фиксируем сразу

Чтобы не обещать невыполнимого (`docs/09-cms-playbooks.md`):

| Хочется | Реальность на Tilda |
|---|---|
| Массово сгенерировать мета по шаблону | Нет. 115 страниц = 115 ручных операций |
| Серверный рендер карточек каталога | Нет. Tilda Store рендерит JS. Лечится только ручными HTML-ссылками в T123 |
| Зелёный PageSpeed | Нет. Рычаги: сжатие картинок до загрузки, минус тяжёлые анимации и слайдеры на первом экране, минус лишние виджеты |
| Настроить заголовки кэширования, HTTP/3, CDN | Нет доступа к серверу |
| Свой `<head>` на конкретную страницу | Код в `<head>` общий для сайта. Постранично — только через T123 в body |
| Произвольная вложенность URL | Ограничена. `/projects/*` — структура каталога, менять рискованно |
| WebP-конвертация | Автоматики нет, только загружать уже сжатое |

**Отдельный риск:** кастомный код в T123 и `<head>` слетает при пересборке страницы
дизайнером. Всё, что вставлено вручную, фиксируется в `tilda-instructions.md`, чтобы
восстановить после любой переделки.

## Формат деливераблов

Доступа в Tilda нет, правки применяет человек. Значит каждая задача пишется как
исполнимая инструкция, а не как рекомендация:

```
Страница «Одноэтажные фахверки» (/odnoehtazhnye)
1. Открыть страницу в редакторе → шестерёнка → «Настройки страницы» → вкладка SEO
2. Поле Title заменить на:
   Одноэтажные фахверковые дома под ключ — проекты и цены в Москве | Inteq Haus
3. Поле Description заменить на:
   <готовый текст>
4. Добавить блок T123 (HTML) перед футером, вставить код: <готовый код со ссылками>
5. Опубликовать страницу
```

Формулировка «оптимизировать мета-теги» недопустима (§8 `CLAUDE.md`).

## Риски

- **Без Яндекс.Вебмастера** нельзя подтвердить регион, увидеть фильтры и реальную
  индексацию. Часть аудита останется `[оценка]` до получения доступа — это будет
  явно помечено, а не замазано.
- **Глубина съёма Google = 1 страница** искажает базу. До исправления настройки
  сравнение по Google некорректно.
- **255 из 488 запросов с частотностями** — по остальным приоритизация будет
  предварительной до досбора.
- **Каталог на JS** — если ссылки через T123 не решат задачу, следующий шаг упирается
  в ограничения Tilda Store, и честный ответ может быть «на Tilda дальше не лечится».
