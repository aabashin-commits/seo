# Плагин SearchFit SEO — правила работы

Установлен: `searchfit-seo@knowledge-work-plugins`, scope `user`.
Состав: 11 скиллов, 3 агента, 6 команд.

**Плагин обязателен к использованию** в своей зоне. Не строй процесс с нуля там, где
у него есть готовый скилл. Но и не выдавай его вывод за результат работы.

---

## Полный состав

### Скиллы (активируются автоматически по смыслу задачи)

| Скилл | Назначение |
|---|---|
| `seo-audit` | Комплексный аудит сайта или кодовой базы |
| `technical-seo` | Техничка: CWV, краулинг, индексация, robots, sitemap, скорость |
| `on-page-seo` | Оптимизация конкретной страницы под запрос |
| `broken-links` | Поиск битых ссылок и 404 |
| `internal-linking` | Перелинковка, архитектура, orphan-страницы, распределение веса |
| `schema-markup` | Генерация JSON-LD |
| `content-strategy` | Контент-план, анализ пробелов, редакционный план |
| `content-brief` | Бриф на статью |
| `keyword-clustering` | Группировка ключей в тематические кластеры |
| `ai-visibility` | Присутствие бренда в ответах ChatGPT, Claude, Gemini, Perplexity |
| `content-translation` | Перевод и локализация, hreflang |

### Агенты (запуск только с разрешения)

| Агент | Что делает |
|---|---|
| `seo-auditor` | Автономный аудит сайта со скоринговым отчётом |
| `content-strategist` | Полный контент-план по сайту |
| `competitor-analyzer` | Исследование конкурентов и поиск возможностей |

### Команды с реальными аргументами

```
/seo-check [file]
/generate-schema [type] [file]
    type: article, product, faq, howto, organization, breadcrumb,
          local-business, video, software (автоопределение, если не задан)
/keyword-cluster <keywords> [intent]
    keywords: список через запятую или путь к файлу
    intent: all, informational, commercial, transactional (по умолчанию all)
/create-topic <seed> [count] [audience] [funnel]
/create-content <topic> [type] [words] [tone]
    type: blog, guide, listicle, comparison, how-to, glossary (по умолчанию blog)
    words: по умолчанию 1500
/translate-content <language> [file] [market]
```

## Семь правил

### 1. Плагин — инструмент первого выбора
Есть скилл под задачу — используй. Не пересобирай процесс вручную из принципа.

### 2. Плагин гугловый и англоязычный
Он не знает Яндекса, Wordstat, региональности, коммерческих факторов, «Баден-Бадена»,
специфики Tilda. Его вывод по RU-проекту — черновик.

### 3. Обязательная валидация по четырём осям

**Региональность.** Плагин не спросит про регион. Проверь, учтена ли гео-привязка в
рекомендациях по структуре и мета-тегам.

**Коммерческие факторы.** В гугловой методичке их нет как класса. Добавляешь блок сам
по `06-commercial-local-links.md`.

**Частотности.** Любые числа по объёму спроса от плагина — не из Wordstat. Для RU
пересчитываешь сам либо помечаешь `[оценка, источник: плагин]`.

**CMS.** Рекомендация «добавьте в `<head>`» бессмысленна для клиента на Tilda без
понимания, куда именно. Переводишь в инструкцию по `09-cms-playbooks.md`.

### 4. Конвейер односторонний

```
плагин → work/ (сырьё как есть) → валидация → адаптация → deliverables/
```

Файл не копируется из `work/` в `deliverables/`. Он переписывается тобой.
Прямой путь из плагина в `deliverables/` запрещён без исключений.

### 5. Помечай происхождение данных

В отчёте у каждого блока понятно, откуда он:
- `[плагин]` — получено скиллом, проверено на достоверность.
- `[проверено]` — ты убедился лично (краул, выдача, Вебмастер).
- `[оценка]` — расчёт или экстраполяция, с описанием допущений.

### 6. Агенты — только с разрешения

`seo-auditor`, `content-strategist`, `competitor-analyzer` работают долго и дорого.
Спрашиваешь явно, объясняя, что именно они дадут и почему обычных скиллов мало.
Результат — в `work/`, разбираешь его так же, как вывод скиллов.

### 7. Границы применимости

Плагин **не заменяет** и не пытается заменить:

- Яндекс.Wordstat и любые частотности по RU.
- Яндекс.Вебмастер: регион, диагностика, исключённые страницы.
- Коммерческие факторы и сравнение с топом выдачи.
- Яндекс.Бизнес, Карты, работу с отзывами.
- Ссылочное под RU и анализ доноров.
- Специфику Tilda, Bitrix и самописных CMS.
- Проверку выдачи вживую — это Playwright.

## Что конкретно переписывать в выводе плагина

Проверенные места, где вывод почти всегда требует правки:

| Что выдаёт плагин | Что делаешь |
|---|---|
| Title до 60 символов по гугловой обрезке | Проверяешь по Яндексу, диапазон 50–65 |
| Рекомендация «добавить больше ключей» | Проверяешь плотность, для Яндекса риск фильтра |
| Оценка объёма трафика | Помечаешь `[оценка]` или заменяешь данными Wordstat/GSC |
| Schema без привязки к содержимому | Сверяешь с тем, что реально на странице |
| «Add hreflang» на одноязычном сайте | Отбрасываешь |
| Кластеры без учёта региона | Пересобираешь по региону из карточки |
| Приоритеты задач по своей шкале | Переводишь в «эффект × трудозатраты» |
| Рекомендации по AMP | Отбрасываешь, для RU нерелевантно |

## Быстрый сценарий

Типовой аудит с плагином выглядит так:

1. Читаешь `project-profile.md`.
2. `seo-crawl` по сайту → `data/crawl-<дата>.csv`.
3. Скиллы `seo-audit` и `technical-seo` → `work/plugin-audit-<дата>.md`.
4. Яндексовый чек-лист вручную → `work/yandex-check-<дата>.md`.
5. Коммерческие факторы сравнением с топ-5 → `work/commercial-<дата>.md`.
6. Сводишь три источника, разрешаешь противоречия, приоритизируешь.
7. `deliverables/audit-<домен>-<дата>.md` + `task-list-<домен>-<дата>.csv`.

Шаги 4 и 5 пропустить нельзя — именно они отличают работу senior-специалиста от
пересказа вывода инструмента.
