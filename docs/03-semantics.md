# Семантическое ядро

Цель — файл `data/semantic-core.csv`, в котором каждая строка это запрос с честной
частотностью, типом интента и пометкой, брать его в работу или нет.

## Источники под RU

| Источник | Что даёт | Доступ |
|---|---|---|
| Яндекс.Wordstat | Базовая частотность, связанные запросы, регионы, сезонность | Бесплатно |
| Подсказки Яндекса и Google | Живой спрос, длинный хвост | Бесплатно, собирается Playwright |
| «Вместе с этим ищут» / «Похожие запросы» | Расширение и соседние интенты | Бесплатно |
| Яндекс.Вебмастер → «Запросы» | Реальные показы и клики сайта | Если есть доступ |
| Google Search Console | Запросы, позиции, CTR | Если есть доступ |
| Ahrefs / Semrush / Keys.so / Serpstat | Запросы конкурентов, объёмы | Если есть в проекте |
| Прайс, каталог, скрипты продаж клиента | Коммерческая лексика, которой нет в тулзах | Всегда запрашивай |

Отсутствие платных тулзов не блокирует работу: Wordstat + подсказки + выдача +
внутренние данные клиента закрывают ядро для проекта на услуги или инфосайт.

## Операторы Wordstat

Основа честных частотностей. Проверено, работает.

| Запись | Что показывает |
|---|---|
| `ремонт квартир` | Базовая частота: запрос и все, что его содержат, в любых словоформах |
| `"ремонт квартир"` | Фразовая: только эти слова, любой порядок, любые окончания |
| `"!ремонт !квартир"` | Точная: эти слова в этой форме, без добавок |
| `+в москве` | Принудительно учитывает предлог или союз |
| `-дешево` | Исключает слово |
| `ремонт (квартир\|комнат)` | Группировка вариантов |

**Три частотности пиши в разные колонки, никогда не смешивай:**

- `freq_base` — базовая. Показывает размер темы, но не спрос на конкретный запрос.
- `freq_phrase` — фразовая, `""`.
- `freq_exact` — точная, `"! !"`. **Именно на неё опираешься при приоритизации.**

### Признак накрутки

Базовая частотность высокая, точная — почти ноль (соотношение хуже 1:100). Такой запрос
либо накручен, либо это широкая маска, внутри которой реальный спрос распределён по
длинному хвосту. В работу как отдельный запрос не берётся.

### Регион

Wordstat считает по региону. Всегда выставляй регион из карточки проекта. Частотность
по России для локального бизнеса из Казани — бесполезное число.

### Сезонность

Для тем с явной сезонностью (кондиционеры, шины, отопление, праздники) смотри историю
запросов за 24 месяца. В отчёт по контент-плану сезонность выносится явно: планировать
публикацию нужно за 1,5–2 месяца до пика спроса.

## Сбор

1. **Базис.** Выпиши маркерные запросы — услуги и категории клиента его же словами
   (сайт, прайс, реклама). 20–60 масок для среднего проекта.
2. **Расширение вширь.** Каждую маску прогоняешь через Wordstat, левую и правую колонки.
3. **Расширение вглубь.** Подсказки поиска, «вместе с этим ищут», блок «Быстрые ответы».
4. **Конкуренты.** Если есть платный тулз — выгрузка запросов топ-5 конкурентов.
   Если нет — разбор их структуры URL и заголовков через `seo-crawl`.
5. **Свои данные.** Запросы из Вебмастера и GSC, по которым сайт уже показывается.
   Это самый ценный слой: там сразу видно недобор.
6. **Синонимы и народные формулировки.** «Стоматология» / «зубной» / «лечение зубов»,
   «квартира посуточно» / «снять на сутки». Их не даёт ни один автоматический сбор.

## Чистка

Порядок важен: сначала удаляешь мусор целыми пластами по минус-словам, потом смотришь
остаток руками.

### Минус-слова: базовый набор

**Универсальные:** бесплатно, скачать, торрент, фото, видео, реферат, курсовая, вики,
википедия, форум, отзывы сотрудников, вакансии, работа, зарплата, своими руками, схема,
чертёж, б/у, авито.

**Для услуг и локального бизнеса дополнительно:** обучение, курсы, как стать,
профессия, лицензия, госуслуги, закон, гост, инструкция, самостоятельно.

**Для инфосайтов:** купить, цена, стоимость, заказать, доставка, интернет-магазин —
если сайт не продаёт. Иначе наоборот, это целевые.

**Всегда персонально:** чужие бренды и конкуренты, чужие города, чужие модели товаров,
услуги, которых у клиента нет. Этот список составляется по карточке проекта.

### Ручная проверка остатка

Убираешь:
- Запросы с точной частотностью 0 при базовой выше 100 — фантомы.
- Запросы, для которых у клиента нет ни страницы, ни возможности её сделать.
- Запросы чужого интента: под ним в выдаче только Википедия и форумы, а сайт коммерческий.

## Разметка интента

Каждому запросу проставь тип — от него зависит тип посадочной страницы.

| Интент | Признаки | Тип страницы |
|---|---|---|
| Информационный | как, что такое, почему, инструкция, своими руками | Статья, гайд |
| Коммерческий | купить, заказать, цена, стоимость, услуги, под ключ | Услуга, категория |
| Транзакционный | конкретная модель, артикул, «оформить» | Карточка, форма |
| Навигационный | бренд, название компании, «официальный сайт» | Главная, о компании |
| Гео | город, район, метро, «рядом», «поблизости» | Гео-посадочная |

**Интент определяется выдачей, а не словами.** Если по запросу «ремонт квартир»
в топе агрегаторы и каталоги, а не сайты подрядчиков — это меняет план. Спорные
запросы проверяй в выдаче через Playwright.

## Формат выгрузки

`data/semantic-core.csv`, UTF-8 с BOM, разделитель `,`. Колонки:

```
query,freq_base,freq_phrase,freq_exact,region,intent,cluster,target_url,priority,source,checked_at
```

- `source` — откуда взята частотность (`wordstat`, `gsc`, `ahrefs`).
- `checked_at` — дата снятия. Частотность без даты через полгода бесполезна.
- `cluster` и `target_url` заполняются на следующем этапе (`04-clustering.md`).

## Типовые ошибки

- Приоритизация по базовой частотности. Даёт красивое ядро и нулевой результат.
- Ядро без региона у локального бизнеса.
- Сбор без прайса и без разговора с клиентом — теряется половина коммерческой лексики.
- Тысячи запросов в ядре при сайте на 15 страниц. Ядро должно соответствовать тому,
  сколько страниц реально будет создано.
- Частотности из платного тулза выданы как факт без пометки источника — у Ahrefs и
  Wordstat разные методики, смешивать их в одной колонке нельзя.
