# Плейбуки по CMS

Определи CMS на онбординге (`01-project-onboarding.md`) и запиши в карточку проекта.
От неё зависит, какая рекомендация выполнима, а какая — пустой звук.

---

## Tilda

### Что доступно

| Элемент | Где | Ограничения |
|---|---|---|
| Title, description | Настройки страницы → SEO | Вручную по каждой странице |
| URL страницы | Настройки страницы → Адрес | Кириллица допустима, лучше латиница |
| h1–h3 | Через теги в блоках заголовков | Проверять, какой тег реально ставит блок |
| alt изображений | Настройки блока → изображение | Не у всех блоков есть поле |
| Свой код в `<head>` | Настройки сайта → Ещё → HTML-код для `<head>` | Общий для всего сайта |
| Свой код на странице | Блок T123 (HTML) | Постранично |
| robots.txt | Настройки сайта → Ещё | Редактируется |
| sitemap.xml | Генерируется автоматически | Управление ограничено |
| Редиректы 301 | Настройки сайта → Ещё → Редиректы | Постранично, вручную |
| Микроразметка | Через блок T123 или код в `<head>` | Вручную |

### Ограничения, которые надо знать заранее

- **Скорость.** Рычагов мало: сжатие изображений перед загрузкой, отказ от тяжёлых
  анимаций и слайдеров на первом экране, отключение неиспользуемых виджетов, минимум
  сторонних скриптов. Глубокая оптимизация невозможна — не обещай клиенту зелёный
  PageSpeed.
- **Шаблонные мета.** Массовой генерации title нет. Для сайта на 60 страниц это
  60 ручных операций — закладывай в трудозатраты.
- **Структура URL** жёстко привязана к странице, вложенность ограничена.
- **Динамические страницы** (каталог Tilda) имеют отдельную и более скудную SEO-настройку.
- **Кастомный код** легко ломается при пересборке страницы дизайнером. Предупреждай.

### Как формулировать задачи

Клиент на Tilda обычно правит сам. Задача пишется как пошаговая инструкция:

```
Страница «Ремонт квартир» (/remont-kvartir)
1. Открыть страницу в редакторе → шестерёнка → «Настройки страницы» → вкладка SEO
2. Поле Title заменить на:
   Ремонт квартир в Казани — под ключ за 30 дней | СтройДом
3. Поле Description заменить на:
   Ремонт квартир в Казани под ключ. Фиксированная смета, договор, срок от 30 дней.
   Бесплатный выезд замерщика. Гарантия 3 года.
4. Опубликовать страницу
```

Формулировка «оптимизируйте мета-теги» на Tilda не будет выполнена никогда.

## WordPress

### Что доступно

Практически всё. Основной вопрос — какой SEO-плагин установлен.

| Задача | Инструмент |
|---|---|
| Мета-теги, шаблоны мета | Yoast SEO, Rank Math, All in One SEO |
| Шаблоны для категорий и архивов | Тот же плагин, раздел «Типы записей» |
| robots.txt, sitemap.xml | SEO-плагин |
| Canonical, noindex | SEO-плагин, постранично и по типам |
| Редиректы 301 | Redirection или SEO-плагин |
| Хлебные крошки | SEO-плагин или тема |
| Schema.org | SEO-плагин, для нестандартного — вручную в `functions.php` |
| Скорость | Кеширование, оптимизация изображений, отключение лишних плагинов |

### Типовые находки

- **Архивы автора, дат и тегов** открыты и создают дубли. Закрываются в SEO-плагине.
- **Пагинация** без корректного canonical.
- **Вложения (attachment pages)** открыты — на каждое изображение своя страница.
  Закрываются или редиректятся на запись.
- **Дублирование категории и тега** с одинаковым названием.
- **Плагины-паразиты:** 40 активных плагинов, половина не используется, скорость на дне.
- **Шаблон title вида `%%title%% - %%sitename%%`** по умолчанию — не оптимизирован.

### Шаблоны мета

Сильная сторона WordPress. Для однотипных страниц задаёшь шаблон вместо ручной правки:

```
Записи:      %%title%% — %%category%% | %%sitename%%
Категории:   %%term_title%% — {N} материалов | %%sitename%%
Товары:      %%title%% — купить в {городе}, цена %%price%%
```

Экономит десятки часов на больших сайтах. Обязательно проверь результат на 5–10
страницах: шаблоны легко дают вылезающие за лимит или бессмысленные title.

### Как формулировать задачи

Если правит разработчик — тикет с точным «было → стало». Если клиент — инструкция с
названием плагина и путём в меню.

## Самописные сайты

### Что выяснить в первую очередь

1. Кто разработчик и есть ли он вообще в наличии.
2. Есть ли админка и что в ней можно менять без разработчика.
3. Есть ли доступ к репозиторию и деплою.
4. Технология: серверный рендеринг или SPA на JS.

**Если контент отдаётся только после выполнения JS** — это первая по важности находка.
Проверяется сравнением HTML из `curl` и из Playwright после рендера. Для Яндекса это
критично.

### Формат задач

Тикет разработчику. Обязательные поля:

```
Заголовок:   Добавить canonical на страницы пагинации каталога
Где:         Шаблон страницы каталога, /catalog/*?page=N
Что сейчас:  canonical отсутствует
Что нужно:   <link rel="canonical" href="https://домен/catalog/"> на всех страницах
             пагинации начиная со второй
Почему:      Страницы пагинации индексируются как дубли категории, размывают
             релевантность. В индексе 340 таких страниц.
Проверка:    В исходном коде /catalog/?page=2 присутствует canonical на /catalog/
Приоритет:   Высокий эффект, 2 ч разработчика
```

Расплывчатая формулировка возвращается с вопросами и теряет неделю.

### Что часто отсутствует и надо проверить

- `robots.txt` и `sitemap.xml` вообще нет.
- 404 отдаёт код 200.
- Нет редиректа http→https или www.
- Одна и та же страница доступна по нескольким URL.
- Title генерируется из названия раздела без шаблона.
- Нет `alt`, нет микроразметки.
- Открыт тестовый контур на поддомене.

## Bitrix (встречается в RU часто)

Если попадётся, ключевые точки:

- Мета-шаблоны настраиваются в свойствах инфоблока — там же массовая генерация.
- «Умный фильтр» плодит дубли: нужен canonical и продуманное правило индексации фильтров.
- Композитный сайт и кеширование — основной рычаг скорости.
- Модуль «Поисковая оптимизация» закрывает базовые задачи.
- Стандартные проблемы: `/index.php` доступен наряду с `/`, дубли с параметрами
  сортировки, тяжёлые неоптимизированные шаблоны.

## Универсальное правило

Перед тем как записать задачу в отчёт, ответь на вопрос: **кто и в каком интерфейсе
физически это сделает.** Если ответа нет — задача сформулирована неправильно.
