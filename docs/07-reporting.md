# Приоритизация и отчётность

## Модель приоритизации: эффект × трудозатраты

### Эффект

| Уровень | Признаки |
|---|---|
| **Высокий** | Блокирует индексацию, затрагивает весь сайт или приоритетные посадочные, открывает доступ к кластеру с большой суммарной частотностью |
| **Средний** | Затрагивает раздел, улучшает позиции уже ранжирующихся страниц, повышает CTR |
| **Низкий** | Точечное улучшение, эффект отложенный или косвенный |

Уровень всегда сопровождается обоснованием в одну строку: **за счёт чего** эффект.
«Высокий» без обоснования — не приоритет, а мнение.

### Трудозатраты

Оцениваются в часах и с указанием исполнителя:

| Исполнитель | Типовые задачи |
|---|---|
| SEO | Мета-теги, семантика, ТЗ, перелинковка, разметка |
| Разработчик | Редиректы, robots, sitemap, скорость, шаблоны, canonical |
| Копирайтер | Тексты по ТЗ |
| Клиент | Цены, фото, документы, отзывы, карточка в Яндекс.Бизнес |

Задача без указания исполнителя не будет сделана — она повиснет между всеми.

### Быстрые победы

Отдельный блок в начале отчёта: **высокий эффект при трудозатратах до 2 часов**.
Обычно это:
- Открытие важных страниц от noindex.
- Исправление robots.txt, блокирующего нужное.
- Назначение региона в Вебмастере.
- Мета-теги на 10–20 приоритетных страницах.
- Устранение цепочек редиректов.
- Заполнение карточки Яндекс.Бизнес.

Блок нужен потому, что клиент оценивает работу по первому видимому результату.

### Порядок в отчёте

1. Быстрые победы.
2. Высокий эффект / любые трудозатраты.
3. Средний эффект / до 8 часов.
4. Остальное — списком «сделать позже».

Внутри группы сортируй по возрастанию трудозатрат.

## Формулировка задачи

Каждая задача содержит четыре элемента:

1. **Что сделать** — конкретно, с указанием объекта. Не «оптимизировать мета-теги»,
   а «переписать title на 23 страницах категорий по формуле из приложения».
2. **Почему** — какая проблема решается и чем она грозит.
3. **Как проверить** — по какому признаку задача считается выполненной.
4. **Кто делает** и **сколько это займёт**.

### Плохо и хорошо

**Плохо:** «Улучшить скорость загрузки сайта.»

**Хорошо:** «Сжать изображения в каталоге (312 файлов, суммарно 48 МБ) до WebP и
проставить `width`/`height`. Сейчас LCP на мобильных 4,8 с при норме до 2,5 с —
это повышает отказы и режет позиции в обеих ПС. Проверка: LCP ниже 2,5 с в
PageSpeed Insights на мобильных для страниц каталога. Исполнитель: разработчик, 6 ч.»

## Структура отчёта клиенту

Шаблон: `templates/audit-report.md`.

```
1. Резюме на одну страницу      что нашли, что это стоит, с чего начать
2. Быстрые победы               3–7 пунктов, до 2 часов каждый
3. Критичное                    что режет трафик прямо сейчас
4. Техническая часть            по разделам чек-листа
5. Семантика и структура        карта релевантности, пробелы
6. Контент                      что переписать, что создать, что удалить
7. Коммерческие факторы         сравнение с топ-5 конкурентов
8. Нужны данные                 доступы и выгрузки, которые дадут точность
9. План на 1–3 месяца           последовательность, не свалка задач
```

### Правила подачи

- **Резюме пишется последним и читается первым.** Клиент часто читает только его.
- Каждое число сопровождается источником и датой.
- Разделяй `[факт]` и `[оценка]`. Прогноз трафика без данных — всегда оценка с
  описанием допущений.
- Не обещай позиций и сроков выхода в топ. Обещай выполнение работ и описывай,
  какой эффект они дают.
- Скриншоты и выдержки из данных — там, где иначе не поверят.
- Раздел «Нужны данные» обязателен даже когда всё есть: там перечисляется, что
  позволит работать точнее в следующем цикле.

## Подготовка файлов под Google Drive

Google Drive MCP не подключён — файлы готовятся локально, заливает человек.

### Markdown → Google Docs

- Заголовки только через `#`, `##`, `###` — при импорте станут стилями.
- Таблицы обычным Markdown-синтаксисом переносятся корректно.
- Не использовать HTML внутри Markdown — не переживёт импорт.
- Изображения — отдельными файлами рядом, ссылками. Встроенные base64 не импортируются.
- Файл называть по схеме `<тип>-<домен>-<ГГГГ-ММ-ДД>.md`.

### CSV → Google Sheets

- Кодировка **UTF-8 с BOM**, иначе кириллица распадётся.
- Разделитель `,`. Значения с запятыми и переносами — в двойных кавычках.
- Первая строка — заголовки на латинице, без пробелов.
- Числа без пробелов-разделителей разрядов и без символа валюты: `12900`, не `12 900 ₽`.
  Единицу выноси в название колонки.
- Даты в `ГГГГ-ММ-ДД`.
- Одна таблица — один файл. Не склеивать несколько таблиц в один CSV.

Проверка перед сдачей: открыть файл и убедиться, что первая строка — заголовки, а
колонки не разъехались на строках с запятыми внутри значений.

### Именование в `deliverables/`

```
audit-<домен>-2026-08-25.md
task-list-<домен>-2026-08-25.csv
relevance-map-<домен>-2026-08-25.csv
brief-<url-slug>-2026-08-25.md
```

Дата в имени обязательна: клиенту отдаются версии, и через месяц надо понимать, какая
из них актуальна.

## Регулярная отчётность

Если проект ведётся на постоянной основе, ежемесячный отчёт короче аудита:

1. Что сделано за период — списком, со ссылками на страницы.
2. Динамика: трафик, позиции по приоритетным кластерам, показы и CTR.
3. Что изменилось не по нашей вине: апдейты ПС, действия конкурентов, сезонность.
4. Что делаем в следующем периоде.
5. Что блокирует работу — задачи на стороне клиента, не сделанные с прошлого раза.

Пункт 5 самый важный и его чаще всего пропускают. Без него через три месяца
непонятно, почему нет результата.
