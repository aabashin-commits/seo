# Технический аудит

Аудит состоит из двух чек-листов: **общий** (работает для обеих ПС) и **яндексовый**
(то, чего нет в гугловых методичках и чего не знает плагин SearchFit).

## Подготовка

1. Прочитай карточку проекта: регион, CMS, масштаб, доступы.
2. Собери краул: скилл `seo-crawl` либо разбор выгрузки Screaming Frog / Netpeak из `data/`.
3. Если есть Вебмастер и GSC — выгрузи отчёты по индексации и ошибкам в `data/`.
4. Запусти скиллы плагина `seo-audit` и `technical-seo`, положи вывод в `work/`.
   Дальше проверяешь его по этим чек-листам, а не принимаешь на веру.

## Общий чек-лист

### Доступность и коды ответа

| Проверка | Норма | Как проверить |
|---|---|---|
| Главная | 200 | `curl -I` |
| Несуществующий URL | 404 или 410, не 200 | запрос `/nesushestvuyushaya-stranica-test-123` |
| http → https | 301 | запрос по http |
| www ↔ без www | 301 в одну сторону | оба варианта |
| Слеш на конце | 301 в один канонический вид | `/page` и `/page/` |
| Верхний регистр в URL | 301 на нижний | `/Page` |
| Цепочки редиректов | не длиннее 1 шага | краул |
| Битые внутренние ссылки | 0 | краул, скилл `broken-links` |
| 5xx в краулe | 0 | краул |

**Мягкий 404** — самая частая незамеченная проблема: страница «ничего не найдено» отдаёт
200. Проверяется всегда, на Tilda и самописных встречается регулярно.

### Индексация

- `robots.txt` существует, отдаёт 200, не блокирует CSS и JS.
- Директива `Sitemap:` в `robots.txt` присутствует и ведёт на живой файл.
- `sitemap.xml` отдаёт 200, содержит только страницы с кодом 200 и без noindex,
  не содержит canonical-дублей, размер до 50 000 URL и до 50 МБ на файл.
- Нет страниц одновременно в sitemap и под `noindex` — это прямое противоречие сигналов.
- Служебные разделы (корзина, личный кабинет, результаты поиска по сайту, UTM-версии)
  закрыты от индексации.
- Разрыв между числом страниц в sitemap и числом в индексе — считается и объясняется.
  Расхождение больше 20 % требует разбора причины, а не упоминания в отчёте.

### Дубли и каноникализация

Проверяй источники дублей по списку, он почти исчерпывающий:

1. Параметры сортировки и фильтров (`?sort=`, `?filter=`).
2. UTM-метки и `?gclid`, `?yclid`.
3. Пагинация без корректного canonical.
4. Один товар/статья доступен по нескольким путям.
5. Печатные версии, AMP-остатки.
6. Поддомены-копии, тестовые контуры (`dev.`, `staging.`, `old.`) в открытом доступе.

Правила: `canonical` абсолютный, ведёт на страницу с кодом 200, страница ссылается сама
на себя, если она каноническая. Цепочки canonical запрещены.

**Открытый тестовый контур в индексе** — критичная находка уровня P0, ищи его всегда:
`site:dev.домен`, `site:staging.домен`, `site:old.домен`.

### Заголовки и мета

| Элемент | Норма | Порог для задачи |
|---|---|---|
| `title` | уникален на каждой странице | дубли > 5 % страниц → задача |
| `title` длина | 50–65 символов | > 70 или < 25 → задача |
| `description` | уникален, 120–160 символов | пустых > 10 % → задача |
| `h1` | ровно один на странице | 0 или > 1 → задача |
| Иерархия h2–h3 | без пропусков уровней | системный пропуск → задача |
| `alt` у изображений | заполнен у контентных | пустых > 30 % → задача |

Формулы генерации title и description — в `05-content-onpage.md`.

### Скорость и Core Web Vitals

Пороговые значения Google (мобильная версия, 75-й перцентиль):

| Метрика | Хорошо | Требует улучшения | Плохо |
|---|---|---|---|
| LCP | ≤ 2,5 с | 2,5–4,0 с | > 4,0 с |
| INP | ≤ 200 мс | 200–500 мс | > 500 мс |
| CLS | ≤ 0,1 | 0,1–0,25 | > 0,25 |

Замеряй мобильную версию — она приоритетна для обеих ПС. Типовые причины проблем в
порядке частоты: неоптимизированные изображения без `width`/`height`, сторонние скрипты
аналитики и виджетов, шрифты без `font-display: swap`, отсутствие кеширования, тяжёлые
слайдеры на первом экране.

Для Tilda набор рычагов ограничен — см. `09-cms-playbooks.md`.

### Мобильная версия и рендеринг

- Контент мобильной версии совпадает с десктопной (не урезан).
- Нет горизонтального скролла, тап-таргеты не слипаются.
- Контент виден без JavaScript либо отдаётся сервером. Проверка: сравни HTML из
  `curl` и из Playwright после рендера. **Если ключевой текст и ссылки появляются
  только после JS — это находка, для Яндекса особенно.**

### Безопасность и прочее

- Валидный сертификат, нет смешанного контента.
- Нет висящих ссылок на внешние домены с истёкшей регистрацией.
- Нет следов взлома: скрытые ссылки в футере, посторонние страницы в индексе,
  инъекции в `robots.txt`.

## Яндексовый чек-лист

Этого нет в SearchFit и в большинстве англоязычных методичек. Делаешь сам.

### Региональность

Ключевой фактор ранжирования по коммерческим запросам в Яндексе.

1. В Яндекс.Вебмастере → «Информация о сайте» → «Региональность» назначен регион,
   соответствующий реальной географии бизнеса.
2. Регион подтверждается контентом: адрес, телефон с городским кодом, страница «Контакты».
3. Для мультирегионального бизнеса — отдельные посадочные под города и/или поддомены,
   каждый со своим регионом. Не одна страница со списком двадцати городов.
4. Компания добавлена в Яндекс.Бизнес, карточка подтверждена, данные совпадают с сайтом.

Ошибка «регион не назначен» у коммерческого сайта — находка уровня P0.

### Яндекс.Вебмастер

- Раздел «Диагностика» — разобрать все сообщения, не игнорировать «рекомендации».
- «Страницы в поиске» — динамика, разделы «Исключённые страницы» и причины исключения.
  Массовое «Недостаточно качественная» — сигнал о проблеме с контентом, а не техничкой.
- «Мониторинг важных страниц» — настроен на ключевые посадочные.
- ИКС (индекс качества сайта) — фиксируй значение и динамику, но не строй на нём выводов:
  это индикатор, а не рычаг.
- «Товары и цены», «Организации» — заполнены, если применимо.

### Требования Яндекса к текстам

Яндекс жёстче Google относится к переоптимизации. Фильтр «Баден-Баден» накладывается за
тексты, написанные для робота.

Признаки, которые ищешь в аудите:
- SEO-текст внизу страницы категории, который не читают люди.
- Перечисление городов или словоформ списком.
- Плотность вхождений ключа выше 3–4 % от текста.
- Одинаковые «уникализированные» тексты на десятках страниц.

Такой текст лучше удалить, чем переписать. Это отдельная задача в отчёте с обоснованием.

### Поведенческие факторы

Прямо оптимизировать нельзя, но техаудит на них влияет:
- Скорость загрузки (отказы).
- Понятность первого экрана: что за компания, что предлагает, как связаться.
- Работоспособность форм и телефонов — проверь физически через Playwright.
- Отсутствие агрессивных попапов на входе.

### Чего больше нет

**Турбо-страницы Яндекс отключил в апреле 2025.** В чек-лист не входят. Если на сайте
остались ссылки или разметка Турбо — это мусор, задача на удаление.

## Оформление результата

1. Черновик и вывод плагина остаются в `work/`.
2. Итог — `deliverables/audit-<домен>-<ГГГГ-ММ-ДД>.md` по `templates/audit-report.md`.
3. Задачи — `deliverables/task-list.csv` по модели «эффект × трудозатраты»
   (см. `07-reporting.md`).
4. Каждая находка: **что не так → чем это грозит → что сделать → как проверить**.
   Находка без «как проверить» не считается закрытой.
